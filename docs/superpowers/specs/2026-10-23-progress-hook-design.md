# Хук прогресса и коммит на задачу — дизайн

Дата: 2026-10-23. Дополняет основную спецификацию `2026-10-20-paraplane-design.md` (§5.1, §7, §7.1, §8, §12a);
после реализации её разделы обновляются и остаются источником правды.

## 1. Проблема

1. Прогресс появляется, только если координатор сам вызвал `paraplane progress` и переписал вывод в ответ.
   Правило он пропускает, а вывод инструмента пользователь обычно не видит.
2. paraplane знает о сделанном только по коммиту волны (`Paraplane-Wave`) и по `--done` от координатора.
   Проект, правила которого требуют **коммит на задачу**, ломает и прогресс (первый же коммит задачи с
   `Paraplane-Wave` закрывает всю волну), и аудит (он видит только незакоммиченное).

## 2. Цель

- Прогресс показывается пользователю сам, без участия модели, в моменты из ключа `progress`:
  `wave` (по умолчанию) — когда волна сделана, `task` — когда сделана задача. Закоммичено или нет — неважно.
- Сделанное paraplane узнаёт из четырёх источников: коммит волны, коммит задачи, вернувшийся субагент
  задачи, `--done` координатора.
- Поддерживаются три схемы коммитов: на волну (по умолчанию), на этап (несколько `Paraplane-Wave`, v1.1.1),
  на задачу (`Paraplane-Task`). Аудит работает при любой из них.

Вне рамок: настройки через `/plugin` (`userConfig`); `.paraplane/config.yaml` остаётся единственным источником
настроек.

## 3. Проверенные факты Claude Code (2026-10-23)

- `systemMessage` из `PostToolUse` показывается пользователю в интерфейсе — проверено живым хуком в этом
  проекте. `additionalContext` видит только модель.
- `PostToolUse` с matcher `Agent` получает `tool_input.prompt` и `tool_response` вернувшегося субагента
  (инструмент `Agent`, раньше `Task`; matcher — `Agent|Task`).
- Каталог `.git` репозитория доступен и хуку, и CLI; `CLAUDE_PLUGIN_DATA` командам Bash-инструмента не
  передаётся, поэтому состояние хранится не там (п. 5).
- Codex: инструмента субагентов нет; показ `systemMessage` из его `PostToolUse` не проверен (п. 8).

## 4. Источники «сделано»

Задача **сделана**, если выполнено любое:
1. коммит текущей ветки с трейлерами `Paraplane-Plan: <план>` и `Paraplane-Task: <id>` (несколько
   `Paraplane-Task` в одном коммите — все засчитываются);
2. её волна закрыта коммитом с `Paraplane-Wave: <id волны>` (как сейчас, несколько на коммит — v1.1.1);
3. вернулся субагент, в промпте которого есть строка `Paraplane-Task: <план> <id>` (п. 6), — записано в
   состояние (п. 5);
4. id передан в `paraplane progress --done` (как сейчас).

Волна **сделана**, если у неё есть коммит `Paraplane-Wave` или сделаны все её задачи. Состояния волн
(`done`/`running`/`waiting`) — по правилу §7.1 с этим определением.

`gitx.WaveCommits` превращается в `gitx.PlanCommits(root, planPath) (Commits, error)`:
`Commits{Waves []string; Tasks []string; Lost []LostTrailer}`; `git log` читает коммиты со строкой
`Paraplane-Wave:` или `Paraplane-Task:` (`-i --grep=^paraplane-wave: --grep=^paraplane-task:`).
`LostTrailer` получает поле `Kind` (`wave`/`task`); предупреждение о потерянной задаче —
`warning: task <id> commit <hash>: trailers not in the last paragraph`.

Задача, сделанная по коммиту, но принадлежащая `waiting`-волне, — `warning: task <id> was committed before
<running id>` (аналог предупреждения о волне); в подсчёт она не входит.

## 5. Состояние: задачи вернувшихся субагентов

Файл `<git-dir>/paraplane/closed.json` (`git rev-parse --git-dir`; в worktree — свой). Не коммитится, не
мешает аудиту (вне рабочего дерева). Формат:

```json
{"version":1,"lastHead":"<sha>","entries":[{"plan":"docs/plans/x.md","task":"T3","head":"<sha HEAD на момент записи>"}],
 "shown":{"docs/plans/x.md":{"waves":1,"tasks":4}}}
```

- Запись добавляет только хук (п. 7). Чтение — хук и `paraplane progress`.
- Запись **действительна**, если её `head` — предок текущего `HEAD` или равен ему
  (`git merge-base --is-ancestor`). После `git reset` на более ранний коммит записи, сделанные позже,
  отбрасываются при следующей записи файла.
- `shown` — сколько волн и задач было сделано при последнем показе прогресса плана: защита от повторов.
- `lastHead` — `HEAD`, на котором хук последний раз смотрел коммиты (п. 7).
- Файл читается через `fsx` (только обычный файл, ≤ 1 МБ), пишется атомарно (временный файл + rename).
- Субагенты одной волны возвращаются почти одновременно, поэтому цикл «прочитать — изменить — записать» идёт
  под блокировкой: файл `closed.json.lock`, создаваемый с `O_EXCL`; ожидание до 2 с, блокировка старше 30 с
  считается брошенной и снимается. Не дождался — хук пропускает запись и показ (молча).
  Нечитаемый или битый файл = пустое состояние (молча), при следующей записи перезаписывается.
- Не больше 4096 записей; при переполнении отбрасываются самые старые.

`paraplane progress` без `--done` теперь учитывает и состояние: закрытые = коммиты задач ∪ состояние ∪
`--done`. Флаг `--done` остаётся (Codex, исполнение без субагентов).

## 6. Правила исполнения

- Промпт каждого субагента содержит отдельную строку `Paraplane-Task: <путь плана от корня> <id задачи>`
  (добавляется к уже обязательным `owns`, `reads`, `verify`).
- Схемы коммитов (выбор — по правилам проекта, иначе на волну):
  - на волну — как сейчас;
  - на этап — по `Paraplane-Wave` на каждую волну этапа;
  - на задачу — координатор коммитит задачу после её ревью, по одной (субагенты по-прежнему не коммитят),
    с `Paraplane-Plan` и `Paraplane-Task: <id>`; волна дополнительным коммитом не нужна.
- Трейлеры — в последнем абзаце, вместе с `Co-Authored-By` (как в v1.1.0).
- Claude Code: прогресс показывает хук; координатор его не повторяет (может по просьбе пользователя).
  Codex: координатор показывает прогресс сам, как сейчас (п. 8).

Тексты: `execution.md`, `SKILL.md`, `codex.md`, выжимка `ExecDigest` и `sessionTask`.

## 7. Хук прогресса (Claude Code)

Регистрация в `hooks/hooks.json`: `PostToolUse` с matcher `Write|Edit|Bash|Agent|Task` (одна команда
`hook post-tool-use`, обработчик выбирает по `tool_name`). Write/Edit — как сейчас.

**`Agent`/`Task`:** из `tool_input.prompt` берутся строки `Paraplane-Task: <план> <id>` (план — путь, который
после `rootRel` совпадает с `plan_paths` и является обычным файлом; id по правилу плана; не больше 16 строк).
Каждая пара записывается в состояние с текущим `HEAD`. Затем — показ (ниже).

**`Bash`:** только если в `tool_input.command` есть одно из слов `commit`, `merge`, `cherry-pick`, `rebase`,
`am`, `pull`, `revert` (дешёвая проверка до любого запуска git).
Хук сравнивает `HEAD` с `lastHead` из состояния; при изменении берёт коммиты `lastHead..HEAD` (или один
`HEAD`, если `lastHead` нет или не предок) с трейлерами `Paraplane-Plan` и показывает прогресс каждого
названного плана (не больше 8 планов). `lastHead` хранится в состоянии.

**Показ.** Для плана считаются сделанные волны `W` и задачи `T` (п. 4). Сравнение с `shown`:
- `progress: wave` — показать, если `W` больше `shown.waves`;
- `progress: task` — показать, если `T` больше `shown.tasks` (или `W` больше `shown.waves`).

Показ = ответ хука `{"systemMessage": <вывод progress>, "hookSpecificOutput": {"hookEventName": "PostToolUse",
"additionalContext": "paraplane: progress of <план> was shown to the user; do not repeat it."}}`, затем
`shown` обновляется. Несколько планов — выводы через пустую строку. Предупреждения `progress` (потерянные
трейлеры, коммит вне порядка) входят в вывод. План с ошибками E, нет git, старый git — хук молчит.

Дедлайн и ошибки — как у остальных хуков: 5 с, внутренняя ошибка — пустой ответ (fail-open).

## 8. Codex

Инструмента субагентов нет, поэтому источник 3 недоступен. `PostToolUse` на `Bash` с `commit` в команде
работает так же, но, пока показ `systemMessage` в Codex не проверен, хук отдаёт вывод в `additionalContext` с
просьбой показать его пользователю в блоке кода. Проверка — пункт ручной проверки §8.1 основной спеки; после
неё Codex переходит на `systemMessage`.

## 9. Аудит при коммитах задач

`paraplane audit <plan> <wave>` проверяет не только рабочее дерево, но и коммиты волны текущей ветки:
коммиты с `Paraplane-Plan` = план и `Paraplane-Task`, называющим задачу этой волны, или `Paraplane-Wave` =
эта волна. Список файлов коммита — `git log --name-only --no-renames` (слияния без файлов не проверяются).

- Файл коммита задачи `T3` должен входить в `owns` именно `T3` (а не любой задачи волны):
  `error A1 W2: internal/x.go changed by T3 (commit abc1234) but T3 does not own it`.
- Файл коммита волны — в `owns` любой задачи волны. Коммит этапа (несколько `Paraplane-Wave`) проверяется
  против всех названных в нём волн: файл должен входить в `owns` любой задачи любой из них, иначе
  `error A1 W2: internal/x.go changed in commit abc1234 but no task of W1, W2 owns it`. Аудит такого коммита
  выполняется при аудите любой из его волн; одинаковые находки не повторяются.
- Рабочее дерево — как сейчас. Файл плана и `audit_ignore` исключены везде.
- Итог: `audit ok: W2, 5 changed file(s), 2 commit(s)`; без коммитов — прежний вид.

Те же защиты git, что у `Changed` (фильтры, partial clone, лимит вывода 16 МиБ).

## 10. Затрагиваемые модули

- `internal/gitx` — `PlanCommits` (волны, задачи, потерянные), файлы коммитов волны, `HEAD`/`is-ancestor`,
  путь `git-dir`.
- `internal/progress` — без изменений API (`RenderClosed`); новый текст предупреждения о задаче вне порядка.
- `internal/state` (новый) — чтение/запись `closed.json`, валидность записей, `shown`, `lastHead`.
- `internal/rules` — `Audit` получает файлы коммитов с задачей; новые тексты A1.
- `internal/hooks` — `PostToolUse` для `Agent`/`Task` и `Bash` (Claude), Codex `Bash`; разбор строк
  `Paraplane-Task`; показ.
- `cmd/paraplane` — `progress` читает состояние и `PlanCommits`; `audit` — коммиты волны.
- `hooks/hooks.json`, `hooks/README*`, `skills/rules/**`, `skills/progress`, README, справочник, основная
  спека, `context/`.

## 11. Тесты

- gitx: `Paraplane-Task` один и несколько в коммите; потерянный `Paraplane-Task`; файлы коммитов волны.
- state: битый/чужой файл → пустое; `head` не предок → запись отброшена; лимит записей; атомарная запись.
- progress/CLI: задача по коммиту засчитана, волна из задач-коммитов `done`; задача `waiting`-волны по
  коммиту → предупреждение; состояние + `--done` вместе.
- audit: коммит задачи с чужим файлом → A1 с `changed by T3`; коммит волны; коммит этапа W1+W2 с файлами обеих
  волн → без находок при аудите W1 и W2, файл вне обеих → A1; смесь коммитов и рабочего дерева.
- hooks: коммит этапа W1+W2 → один показ прогресса с обеими волнами `done`.
- hooks: `Agent` с `Paraplane-Task` → запись и `systemMessage` в режиме `task`, без показа в `wave`, пока волна
  не сделана; последний субагент волны → показ в `wave`; повтор без изменений → молчание; `Bash` без `commit`
  → git не запускается; коммит задачи → показ; Codex → `additionalContext`.
- packaging: `hooks.json` содержит новый matcher, контракт обработчиков в `main_test.go`.
