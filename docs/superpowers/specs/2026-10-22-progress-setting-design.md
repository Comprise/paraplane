# Настройка показа прогресса — дизайн

Дата: 2026-10-22. Дополняет основную спецификацию `2026-10-20-paraplane-design.md` (§7, §7.1, §8, §9);
после реализации её разделы обновляются и остаются источником правды.

## 1. Проблема

Прогресс плана показывается, только если координатор после коммита волны сам вызвал `paraplane progress`
и вставил вывод в сообщение. Внутри волны бар стоит на `0/N`, пока волна не закоммичена, поэтому
пользователь видит «зависший» прогресс, даже когда задачи уже закрыты.

## 2. Цель

- Пользователь проекта выбирает, когда показывается прогресс: после закрытия каждой волны или ещё и после
  закрытия каждой задачи.
- Пользователь в любой момент может сам запросить прогресс командой `/paraplane:progress`.
- Закрытая задача выглядит выполненной (🟩) независимо от того, закоммичена ли её волна.
- Плагин по-прежнему не хранит состояния: что закоммичено, видно по git; что закрыто, но не закоммичено,
  сообщает координатор.

Вне рамок: трейлеры `Paraplane-*`, отделённые пустой строкой от последнего абзаца (отдельный баг), хуки,
сами выводящие прогресс.

## 3. Термины

- **Закрытая задача** — задача, которую координатор принял: её субагент вернулся, ревью (если скилл
  исполнения его делает) прошло.
- **Закрытая волна** — волна, у которой прошли аудит и gate. Коммит волны может быть до или после показа.

## 4. Настройка

Новый ключ `.paraplane/config.yaml`:

| Ключ | По умолчанию | Значения |
|---|---|---|
| `progress` | `wave` | `wave` — прогресс после каждой закрытой волны; `task` — ещё и после каждой закрытой задачи |

Неверное значение (не строка или не `wave`/`task`) — значение по умолчанию и строка в `Problems`, как у
остальных ключей; хук `SessionStart` показывает её в `systemMessage`.

## 5. CLI: `paraplane progress [--done <ids>] <file>`

`--done` — список id задач через запятую без пробелов: задачи, закрытые, но ещё не закоммиченные. Флаг
стоит перед файлом (как `check --suggest`). Пустой список, id не по шаблону id плана или повторный флаг —
ошибка аргументов, код 2.

Состояние (заменяет правило §7.1):
- Волна **закрыта**, если у неё есть коммит с трейлером или все её задачи перечислены в `--done`.
- Волна `done` — закрыта и все предыдущие волны `done`; первая не `done` — `running`; остальные — `waiting`.
- Выполненные задачи — все задачи `done`-волн и задачи `running`-волны из `--done`.
- Id из `--done`, которого нет в плане, — строка `warning: --done <id> is not a task of the plan`;
  задача `waiting`-волны — `warning: --done <id> is in waiting wave <W>`; в подсчёт они не входят.
  Предупреждения не меняют код выхода (0).

Вывод (раскладка §7.1 без изменений, кроме подсчёта):
- В строке `running`-волны выполненные задачи — 🟩, остальные — 🟨, в порядке задач волны; `d/n` считает
  выполненные; метка `▶ running`.
- Шапка и полоса: `P` = ⌊100·D/T⌋, где `D` — все выполненные задачи (включая `--done` текущей волны).

Пример (условный: точная ширина колонок — по §7.1): W1 закоммичена, в W2 закрыты T7 и T9 из трёх:

```
$ paraplane progress --done T7,T9 docs/plans/x.md
paraplane · x.md                                           wave 2/3 · 62%
█████████████████████████░░░░░░░░░░░░░░░  5/8 tasks

W1  🟩🟩🟩        3/3  ✓ done     T1 T2 T3
W2  🟩🟨🟩        2/3  ▶ running  T7 T8 T9
W3  ⬜⬜          0/2  · waiting  T10 T11
```

Порядок квадратов — порядок задач в волне: T7 🟩, T8 🟨, T9 🟩.

## 6. Как координатор узнаёт режим

Выжимка правил исполнения (`ExecDigest`: PreToolUse на скилл исполнения в Claude Code, `UserPromptSubmit`
в Codex) получает хвост по режиму из конфига проекта:
- `wave`: «Show the output of \`paraplane progress <plan>\` to the user after each closed wave (audit and
  gate passed); while the wave is not committed yet, pass all its tasks in --done.»
- `task`: то же и «After each closed task (its subagent returned and its review passed) run
  \`paraplane progress --done <closed, uncommitted tasks of the wave> <plan>\` and show the output.»

`ExecDigest` перестаёт быть константой: это функция от режима. Текст проходит `Agent.text`, поэтому в
Codex CLI назван абсолютным путём.

## 7. Правила исполнения (`skills/rules/references/execution.md`)

Шаг 5 «Show progress» заменяется разделом «When to show progress»:
- режим — ключ `progress` в `.paraplane/config.yaml` (по умолчанию `wave`); выжимка правил его называет;
- `wave`: после закрытия каждой волны — `paraplane progress <plan>`; если волна ещё не закоммичена —
  `paraplane progress --done <все задачи волны> <plan>`;
- `task`: дополнительно после закрытия каждой задачи — `paraplane progress --done <закрытые незакоммиченные
  задачи текущей волны> <plan>`;
- вывод всегда вставляется в сообщение пользователю в блоке кода.

`codex.md`, `SKILL.md` и README (`README.md` + `README.ru.md`) получают ту же короткую формулировку и ключ
`progress` в таблице настроек.

## 8. Команда `/paraplane:progress`

Новый скилл `skills/progress/SKILL.md` (Codex: `$paraplane:progress`), вызывается только пользователем
(`disable-model-invocation: true`, `argument-hint: "[plan file]"`, `allowed-tools: Bash(paraplane progress *)`):

1. Выбрать план: путь из аргумента; без него — план, который исполняется в этой сессии; если такого нет —
   самый новый по времени изменения `.md` из `plan_paths` (Glob, как в `/paraplane:check`). Нет плана —
   сказать пользователю и остановиться.
2. Если в сессии исполняется этот план и в текущей волне есть закрытые, но не закоммиченные задачи, —
   передать их в `--done`.
3. Запустить `paraplane progress [--done <ids>] <plan>` и вставить вывод в ответ в блоке кода. Строка
   `error:` или код 2 — сообщить и остановиться. Ничего не менять в плане и коде.

В Codex CLI вызывается по абсолютному пути, как в остальных скиллах.

## 9. Автоодобрение

`bashOwnCLI` пропускает `paraplane progress --done <ids> <path>`, где `<ids>` — id по шаблону плана через
запятую (`[A-Za-z][A-Za-z0-9_.-]*(,[A-Za-z][A-Za-z0-9_.-]*)*`). Codex PermissionRequest использует ту же
проверку для абсолютной формы CLI.

## 10. Затрагиваемые модули

- `internal/config` — ключ `progress`, валидация, `Default()`.
- `internal/progress` — `Render` принимает набор id `--done`, новое правило закрытия волны, предупреждения.
- `cmd/paraplane` — флаг `--done`, usage.
- `internal/hooks` — `ExecDigest(mode)`, `skillDigest`, `PromptSubmit`, `bashOwnCLI`.
- `skills/progress` (новый), `skills/rules`, `skills/README*`, README, основная спецификация, `context/` модулей.
- `internal/plugintest` — новый скилл проходит проверки frontmatter.

## 11. Тесты

- config: `progress: task`, `wave`, неверное значение → `wave` + Problems.
- progress: `--done` в текущей волне (порядок квадратов, `d/n`, процент); все задачи волны в `--done` →
  волна `done`, следующая `running`; id не из плана и из `waiting`-волны → предупреждения; без `--done`
  вывод не меняется (существующие golden-файлы проходят).
- CLI: разбор флага, ошибки аргументов (пустой список, плохой id, флаг дважды, флаг после файла) → код 2.
- plugintest: frontmatter `skills/progress/SKILL.md`, скилл попадает в архив (`ship.txt`).
- hooks: текст выжимки для обоих режимов и обоих агентов; регулярка одобряет `--done T1,T2` и отвергает
  пробелы, `..`, метасимволы.
