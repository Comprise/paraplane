# Политика безопасности

[English](SECURITY.md) | **Русский**

## Поддерживаемые версии

Исправления безопасности получает только последняя минорная версия (та, что в ветке `release`). Исправление выходит новой патч-версией; опубликованный выпуск никогда не переписывается.

## Как сообщить об уязвимости

Об уязвимости сообщайте приватно через GitHub: **Security -> Report a vulnerability** (private vulnerability reporting) в этом репозитории. Не открывайте публичные issue или pull request об уязвимости.

Укажите версию paraplane (`paraplane version`), хост (Claude Code или Codex CLI), операционную систему и минимальный пример воспроизведения. Подтверждённая уязвимость исправляется патч-версией и объявляется в GitHub Security Advisory; затронутый выпуск помечается в его заметках (см. `docs/releasing.ru.md`).

## Область действия

paraplane работает как хук с правами пользователя и читает планы и git-репозитории, которые могут прийти из недоверенных источников. В области действия: способ выполнить код, записать данные за пределы состояния `.git/paraplane` репозитория или повлиять на решения хоста через специально составленные планы, конфиги или данные git.

## Проверка выпуска

Бинарники, архив и `checksums.txt` имеют аттестацию происхождения сборки:

```sh
gh attestation verify libexec/paraplane-linux-amd64 --repo Comprise/paraplane
```
