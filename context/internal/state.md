# internal/state
Состояние вне git: задачи, чьи субагенты вернулись, в `<git-dir>/paraplane/closed.json` под блокировкой.

## Назначение
- Хранит то, чего нет в git (спека 2026-10-23 §5): какие задачи закрыты субагентами (с `HEAD` на момент записи и SHA-256 блока плана `PlanHash`), последний просмотренный `HEAD` хука (`LastHead`), что уже показано пользователю (`Shown`), планы, ждущие показа (`Pending`), и кэш скана коммитов (`Scan`, непрозрачен для пакета, его заполняет `track`).
- Файл лежит в каталоге git, вне рабочего дерева: не коммитится и не попадает в аудит. Репозиторий может быть недоверенным, поэтому содержимое файла проверяется, а файловые операции не выходят за каталог состояния.

## Публичный API / точки входа
- `Load(gitDir) (State, error)` — нет файла, битый JSON, нет поля `version`, симлинк, FIFO, файл > 4 МиБ, `paraplane` не каталог → пустое состояние без ошибки; другая версия → `ErrVersion` (вызывающий тогда не читает и не пишет); прочие ошибки ввода-вывода возвращаются.
- `Update(ctx, gitDir, f)` — блокировка, чтение, `f`, очистка (`clean`), атомарная запись. `ErrBusy` — блокировку не взять до конца `ctx` или путь блокировки не обычный файл; `ErrVersion` — `f` не вызывается, файл не меняется.
- `Exists(gitDir) bool` — есть ли `<gitDir>/paraplane/closed.json` (`Lstat`, любой тип файла); по нему хук прогресса решает, писать ли состояние, когда плана нет.
- `State.Add(e)` — дедуп по `Plan+Task+Head+PlanHash`: повтор переезжает в конец. `Prune(keep)`, `Forget(plan, tasks)`, `TakePending(plans)` (убирает только названные планы). `Closed(plan, valid)` — задачи плана, чей `Head` проходит `valid`, без дублей.

## Структура и поток данных
- Формат: `{"version":1,"lastHead":…,"entries":[{"plan","task","head","planHash"}],"shown":{<план>:{"waves","tasks"}},"pending":[<план>…],"scan":{"head","commits":[…]}}`.
- Все операции идут через `os.Root` каталога `<git-dir>/paraplane` (`Mkdir`, `Lstat`, блокировка, временный файл, `Rename`): симлинк не выводит наружу. Сам `paraplane` должен быть настоящим каталогом (`Lstat`), даже симлинк внутрь `.git` отвергается.
- Чтение: `Lstat` (только обычный файл) → открытие с `O_NONBLOCK` на Unix → `Stat` (обычный файл) → не больше 4 МиБ.
- Очистка при чтении и перед каждой записью: `lastHead` и `scan.head` — только полный хеш (`^[0-9a-f]{40}([0-9a-f]{24})?$`), иначе сбрасываются; запись отбрасывается при неверном id задачи (`ids.Valid`), неполном хеше `head`, пустом плане или плане с элементом `..`, `planHash` не из 64 hex (пустой допустим); дубли записей схлопываются (последняя копия); записи и `pending` обрезаются до 4096 последних; ключи `shown` с плохим путём удаляются.
- Запись: временный файл `closed.json.tmp-<rand>` с `O_EXCL` (подложенный симлинк не открывается), `Write`, `Sync`, `Close`, затем `Rename` с повторами до ~0,5 с (на Windows он падает, пока файл открыт другим процессом).

## Блокировка
- Файл `closed.json.lock`, создаётся с `O_EXCL` (блокировки ОС нет: для Windows нужен `x/sys`).
- Путь блокировки — каталог, симлинк, что угодно кроме обычного файла → `ErrBusy` сразу, без ожидания (S-M1).
- Брошенная блокировка — mtime дальше 11 с от текущего времени в любую сторону (выше 10 с таймаута хука; будущая дата тоже, иначе подложенный файл не состарится). Перехват: `Rename` в уникальное имя `closed.json.lock.stale-<rand>` — из нескольких процессов успевает один; если захваченный файл оказался свежим (между `Lstat` и `Rename` победитель уже создал свою блокировку), он возвращается через `Link` (не затирая более новую) и ожидание продолжается.
- Ожидание — опрос раз в 10 мс до конца `ctx`; без дедлайна в `ctx` ждёт, пока блокировка не освободится или не станет брошенной.

## Инварианты и подводные камни
- Пакет не знает git: годность записи (предок ли её `Head`, тот ли блок плана) решает вызывающий.
- Тестовые швы — переменные пакета: `rename` (`func(*os.Root, old, new) error`), `tempName`, `beforeClaim`. Ожидания проверяются в `testing/synctest`; в пузыре время фиктивное (2000 г.), поэтому mtime блокировки там выставляется явно — иначе реальная дата выглядит «будущей» и брошенной.
- Удаление ещё живой блокировки после 11 с удержания возможно только вне хуков (CLI без дедлайна) и считается допустимым.

## Связи (зависит от / используется в)

- Используется в: `internal/track`, `internal/hooks` (хук прогресса), `cmd/paraplane` (тесты).
