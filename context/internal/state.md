# internal/state
Состояние вне git: задачи, чьи субагенты вернулись, в `<git-dir>/paraplane/closed.json` под блокировкой.

## Назначение
- Хранит то, чего нет в git (спека 2026-10-23 §5): какие задачи закрыты субагентами, `HEAD` на момент записи, последний просмотренный `HEAD` хука (`LastHead`) и что уже показано пользователю (`Shown`).
- Файл лежит в каталоге git, вне рабочего дерева: не коммитится и не попадает в аудит.

## Публичный API / точки входа
- `Load(gitDir) State` — никогда не падает: нет файла, битый JSON, другая версия, симлинк или FIFO → пустое состояние.
- `Update(gitDir, f func(*State)) error` — блокировка, чтение, `f`, обрезка до 4096 записей (старые отбрасываются), атомарная запись (`.tmp` + rename), снятие блокировки; `ErrBusy`, если блокировку не взять за 2 с.
- `State.Closed(plan, valid) []string` — задачи плана, чей `Head` проходит `valid`, без дублей, в порядке записей.

## Структура и поток данных
- Формат: `{"version":1,"lastHead":…,"entries":[{"plan","task","head"}],"shown":{<план>:{"waves","tasks"}}}`.
- Блокировка — файл `closed.json.lock`, создаваемый с `O_EXCL`; старше 30 с считается брошенной и снимается.
- Запись: временный файл через `os.CreateTemp` (O_EXCL, подложенный симлинк не используется), затем `rename` с повторами до ~0,5 с (на Windows он падает, пока файл открыт другим процессом). Каталог `paraplane` должен быть настоящим каталогом, не симлинком.

## Инварианты и подводные камни
- Чтение — только через `fsx.ReadRegular` (обычный файл, ≤ 1 МиБ): хук не должен зависнуть на FIFO.
- Пакет не знает git: валидность записи (предок ли её `Head` текущего `HEAD`) решает вызывающий через `valid`.
- `lockWait` — переменная пакета, тесты её сокращают.

## Связи (зависит от / используется в)
- Зависит от: `internal/fsx`.
- Используется в: `internal/track`, `internal/hooks` (хук прогресса).
