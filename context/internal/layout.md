# internal/layout
Находит конфликты пар задач под дедлайном, строит кратчайшую раскладку (ASAP) и рендерит её блоком paraplane.

## Назначение
- Поставляет `rules` сырые конфликты для E2/E4/E5/E6 и раскладку для W3.
- Даёт `paraplane check --suggest` и хукам текст предложенной раскладки.

## Публичный API / точки входа
- `ConflictsWithin(p, hot, deadline)` → `[]Conflict` или `ErrDeadline`; нулевой дедлайн — без ограничения.
- `SuggestWith(p, cs)` — слои id задач; только для плана без ошибок.
- `Render(p, layers)` — блок ```paraplane с ограждениями.
- `Conflict{A, B, Kind, Path, With}`, виды `OwnsOverlap`, `ReadsOwns`, `HotFile`.

## Структура и поток данных
- `prepare` компилирует owns/reads каждой задачи и заранее вычисляет, какие горячие шаблоны она задевает.
- Перебираются все пары задач в порядке автора; на пару — не больше одного owns-конфликта, по одному reads-конфликту в каждом направлении и по одному hot на общий горячий шаблон.
- `SuggestWith`: предшественники — `depends` плюс более ранняя задача каждой конфликтной пары из разных волн; слой = последний предшественник + 1.
- `Render`: волны `W1…`, задачи без изменений, все строки в двойных кавычках через `strconv.Quote`.

## Инварианты и подводные камни
- Пути должны пройти `pathset.Clean` (это делает `rules.Check`); иначе `Overlaps` даёт неверный ответ.
- Часы проверяются перед каждым вычислением шаблона (`tick`): один `doublestar.Match` может занимать миллисекунды и больше. Горячие шаблоны поэтому проверяются по одному owns за вызов `Touches`.
- `rules` превращает `ErrDeadline` (и `plan.ErrDeadline`) в E0 с текстом `ErrDeadline` и `Result.TimedOut`; хуки до R10 ещё сравнивают текст с `ErrDeadline.Error()` — текст менять согласованно.
- В `Path`/`With` предпочитается литерально равная пара шаблонов: тогда `rules` пишет короткое «both own X» вместо «may overlap». `firstOverlap` ищет её заранее по множеству строк owns второй задачи (`prepared.own`, строится один раз в `prepare`) — равная пара всегда пересекается, поэтому сопоставление не нужно; затем — первая пересекающаяся пара (L14).
- Для owns и hot `A` идёт раньше `B` в порядке автора; для reads `A` — читающая задача, порядок любой.
- `SuggestWith` полагается на отсутствие ошибок: все дуги ведут в строго более раннюю волну автора, поэтому порядок автора топологический и слоёв не больше, чем волн.
- Слои не делятся по `max_parallel`: предложенная раскладка может вызвать W2.
- `Render`: id волн пропускают номера, занятые id задач (общее пространство имён); gate слоя — действующий gate (`wave.gate` → `plan.gate`) самой поздней волны автора среди его задач, пишется только если отличается от `plan.gate`; пустой после `TrimSpace` gate считается незаданным.
- Escape-последовательности `strconv.Quote` для валидного UTF-8 совпадают с escape двойных кавычек YAML — вывод разбирается обратно `plan.Parse`.
