# internal/shellx
Лексер shell-команд для хуков Codex: какие литеральные пути команда читает, правит (`sed -i`) или пишет, и какие команды в ней запускаются.

## Назначение
- Codex не сообщает, какие файлы трогает Bash-команда, поэтому `internal/hooks` (`codex_post.go`) берёт кандидаты в файлы плана из слов команды. Пакет не парсер shell: раскрытия (`$x`, `$(…)`, глобы) остаются текстом, понимается только синтаксис, меняющий границы слов и их роль.

## Публичный API / точки входа
- `Kind` — `Read` < `Edit` < `Write`; больший вид побеждает, когда файл тронут несколько раз.
- `Word{Text, Kind, Old, News}` — слово и вид; у `Edit` `Old` — скрипт `sed` (скрипты через `\n`), `News` — тексты замен его `s`-команд.
- `Words(cmd)` — слова всех простых команд по порядку. Запись: слово после `>`, `>>`, `>|`, `&>`, `>&file`; файлы `tee`; последний аргумент `cp`/`mv`/`install`, а с `-t DIR` — добавочные слова `DIR/<имя источника>`. Правка: файлы `sed -i` с простым `s`-скриптом; иначе (`-f`, пустой или непростой скрипт) — запись. Остальное — чтение.
- `CommandNames(cmd)` — первое слово каждой простой команды, без префиксов `VAR=value`, целей редиректа (`<`, `<<<`, `>` и др.) и дескриптора, приклеенного к `<` (`2<f`): `cd x && git commit` → `cd`, `git`; `echo git commit` → `echo`; `<in git commit` → `git`. Для проверки `git` в хуках.

## Инварианты и подводные камни
- Лексер — структура `lexer` с полями состояния и методом на класс символов (`quote`, `redirect`/`output`/`input`, `heredoc`/`bodies`, `separator`, `arithmetic`, `comment`); ни одна функция пакета не выше цикломатической сложности 25 (gocyclo).
- Концы простой команды: `;`, `&` (не `&>`), `|`, `(`, `)`, перевод строки, обратная кавычка. Кавычки и обратные слэши снимаются; в двойных кавычках `\` экранирует только `"` `\` `$` `` ` `` и перевод строки.
- `N>file` — дескриптор отбрасывается; `>&2`, `>&-` — дублирование дескриптора, файла нет.
- Heredoc (`<<`, `<<-`): разделитель — не слово, тело (строки после следующего перевода строки до строки-разделителя; у `<<-` без ведущих табов) пропускается. `<<<word` — слово читается как файл.
- В `(( ))`, `$(( ))`, `$[ ]` операторы `<`, `>`, `<<` и скобки — арифметика; незакрытая группа заканчивается на `;` или переводе строки (кроме `;` в `for (( ; ; ))`).
- `#` — комментарий только в начале слова после пробела или конца команды, до перевода строки или обратной кавычки; внутри слова (`a#b`, `$#`, `$(c)#x`) это буква.
- `Text` слова состоит из байтов команды (кроме `/`, добавляемого для `cp -t DIR`) и не длиннее неё — это проверяет `FuzzWords`.
- Поведение `Words` совпадает с прежним `shellWords` из `internal/hooks` (сверено дифференциальным фаззингом при переносе); тесты `shellx_test.go` — контракт.

## Связи (зависит от / используется в)
- Зависит только от стандартной библиотеки.
- Используется в: `internal/hooks` (`codex_post.go`: `shellWords` переводит `Word` в кандидаты плана; проверка, задела ли правка блок, остаётся в hooks).
